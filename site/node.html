Run a node

A ZP node keeps its own copy of the chain, checks every block and shares it with other nodes. It runs on a small Ubuntu server and installs with one command; a snapshot skips most of the initial sync.

What you need

Processor
1 CPU core
2 recommended. The node is capped at 1 core.
Memory
2 GB RAM
The node is capped at 2 GB. 4 GB total leaves room for the system.
Disk
20 GB free
Chain about 10 GB plus a 5 GB snapshot download. 40 GB SSD recommended.
Network
Port 9655 TCP
Open inbound so other nodes can connect. Works without it, with fewer peers.

A small cloud server is enough, for example 2 vCPU, 2–4 GB RAM, 40 GB disk on Ubuntu 22.04 or 24.04. The node does not mine.

Install

New Ubuntu server: one line

Install Ubuntu 22.04 or 24.04, connect with ssh root@<server-ip> and paste:

curl -fsSL https://navora.network/install.sh | bash

Nothing else to install first. About 10–20 minutes, most of it the 5 GB snapshot. Run the same line again to update; the chain and the settings are kept. Read the script on GitHub.

What the line does

  1. Prepares the server. Waits for the first automatic updates, adds 2 GB swap when RAM is under 4 GB and there is no swap, installs Git and Docker if they are missing, and opens port 9655 in ufw when ufw is on.
  2. Fetches the setup. Downloads this community repository to ~/zenprotocol: the Docker settings and helper scripts, not the chain.
  3. Gets the node image. A ready image with the official Zen Protocol node release 1.0.13 (program unchanged, on the Mono 6.12 runtime); only its seed list is extended with this site and the seeds in network.json. If the registry is unreachable it builds the same image on the server from the official release package.
  4. Loads a snapshot. The newest community chain snapshot (about 5 GB), checked against its SHA-256 and test-extracted. Chain data only, never a wallet. If no community snapshot is reachable it uses the official Feb-2023 snapshot and syncs the rest from the network. Without a snapshot the node syncs from block 0, which takes many hours.
  5. Starts the node. In the background, restarting after a reboot, capped at 1 CPU and 2 GB RAM. Port 9655 is published for peers (a cloud firewall must allow it, see below); the API (port 11567) stays on the server only, because it controls the node's wallet.

Check it

curl -s http://127.0.0.1:11567/blockchain/info

The node is synced when blocks equals headers. Logs: cd ~/zenprotocol && docker compose logs -f --tail 50. If the server has a cloud firewall (for example Hetzner Cloud Firewall), allow inbound TCP 9655 there.

Manual steps, wallets and every setting: full setup guide on GitHub. Seed address of this site: this-site:9655
